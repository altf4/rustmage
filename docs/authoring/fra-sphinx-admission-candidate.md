# Sphinx's Approach conditional admission candidate

This isolated metadata change prepares admission of Sphinx's Approach only if
the in-progress grouped validation and the separately prepared edge tests pass
against the final integrated sources. The metadata flag is not itself evidence
of a passing run, and this commit must not be integrated before those conditions
and the required independent reviews are satisfied. Regenerate catalogue links
and metadata when the candidate is integrated.

The provenance JSON records the complete frozen Oracle identity, the pinned
XMage card implementation and dependencies, and the linked primary and
mixed-zone test modules. The typed definition implements the two-card draw,
optional exile of the resolving spell and four named graveyard cards, Sphinx
search, battlefield entry, shuffle, and the unlimited deck-copy rule. Existing
tests include ordinary payment, decline and short graveyards, both players,
copy lifecycle, invalid selections, search and restore; the independent payment
tests include synthetic prohibition and replacement cases. Deck and sideboard
counting reaches the current unsupported-card gate, so a positive scenario
with the card physically in a sideboard still requires post-admission testing.

synthetic battlefield redirect and injected stale-incarnation fixtures do not
establish a supported real-card path. General CR 614.17 self-replacement,
copy classification on the battlefield, and projected-funding termination
remain unresolved as described in `fra-mixed-zone-cost-draft.md`; this candidate
does not claim that those unrelated general behaviors are complete. If any
such shared limitation is reachable through the printed Sphinx obligations,
or validation or review finds a defect, retain the gate and repair it first.
