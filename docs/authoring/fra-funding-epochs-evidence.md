# Funding refresh and acquisition evidence at 1bc88a2b

This is a bounded source audit, not a proof of production-search termination.

* `FundingState::apply` (`engine_funding.rs:1546`) spends mana and marks activation use, pays life and counters, taps when required, and projects source departure before refreshing control, source-linked effects, storied state and borrowing. The replacement-aware slow path stages a tentative destination before `cost_departures` commits the adjusted movement. In the direct path it increments death histories only on a committed creature departure (`:1655`); the replacement-aware departure path does so when the departure commits (`engine_cast_cost_planning.rs:390`). `life_lost` and `enduring_story` are monotone booleans. Counter-placement history is recorded when a projected entrant with counters is committed (`engine_funding_entries.rs:1230`), and linked returns process existing exact links; after a return the changed incarnation no longer matches the recorded link (`:163`). These observations do not establish a full bound on all entry and cost helpers.
* `refresh_source_bound_copies` (`engine_funding_linked_copies.rs:4`) chooses an existing layer based on presence and exact incarnation of its source; restoring an earlier layer can reset its saved use bits, so that change must be charged to a bounded layer-expiry or entry event. The routine does not choose a layer based on mana-pool amount.
* `continuous_control::controllers` (`engine_continuous_control.rs:43`) rebuilds from control bases and timestamped effects. Ordinary control and exchange register bases before effects, live control-Aura attachments register target bases during refresh, source-linked Control registers a recipient base, and projected incoming control Auras add bases. It applies an effect only to a target present in its base-derived result. For a fixed set of base/effect rows, attachments and exact live sources, an unchanged source-controller input yields the same result. If an Aura source itself can change controller, it must be a target represented in that base-derived result; otherwise its fallback controller remains unchanged. A formal proof of idempotence through dependency cycles and every entry/copy path is still needed.
* Graveyard acquisition (`engine_graveyard_borrowing.rs:89`) retains an active row only while source, provider, ability origin, controller, exact donor and definition match; otherwise it allocates a fresh slot. Repeated refresh with the same eligible facts retains the row, and `refreshed_slots` (`engine_borrowed_activations.rs:208`) retains its matching slot. The lookup of whether the borrowed activation has been used affects activation availability, not the `current_rows` retention predicate. The controlled player, source ability availability and donor characteristics remain important external inputs.
* A textual scan of `engine_ability_evaluation.rs`, `ability_layers.rs`, `engine_characteristic_layers.rs`, `engine_stat_values.rs`, `engine_graveyard_borrowing.rs`, and `engine_ability_world.rs` found no direct mana-pool or use-marker read in the predicate building graveyard acquisition rows. The latter file does expose use markers for activation availability and `.mana` fields for granted ability results, which are different from the player's mana pool. The scan does not close the transitive callback graph or prove that every generated rule is covered.

An event hierarchy remains a plausible direction: bound the initial link returns and resulting departures; between such entries/departures, bound taps, decreasing life and counter payments, monotone history flips, and source-copy layer expiries; charge any control/borrowing epoch reset to one of those events. Before using this as a termination guarantee, prove that no mana-only step can change any acquisition predicate through an unexamined callback, that control projection reaches a stable result without eventful changes, and that all generated/borrowed mana abilities consume a bounded opportunity.
