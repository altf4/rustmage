# Owned token and counter replacement events

Issue [248](https://github.com/altf4/rustmage/issues/248) adds immutable replacement programs and sparse, snapshot-owned event continuations. This author branch starts at reviewed main `74c1f0c3bbad0fc2bcf0e251d13abb655af86e6b`.

The complete bodies are Doubling Season, Exalted Sunborn, Loading Zone, Michelangelo, Weirdness to 11, Yoshimaru, Beloved Companion, Caradora, Heart of Alacria, Quina, Qu Gourmet, and Draconic Visitor. Exact source-name normalization also admits the complete Bartolomé del Presidio sacrifice/counter body. Every remaining sentence must pass the existing complete-body compiler. The current standalone catalogue contains 1,716 supported Standard identities, 84 token recipes and observation schema 74. Standalone acceptance results follow; final integration and independent review remain required.

A counter event captures recipient identity, characteristics, controller, quantity by kind, and effect/cost provenance. Entry counters are staged before object entry and include initial planeswalker loyalty. Ordinary loyalty activation counters remain costs. Replacements re-evaluate applicability after each application, preserving CR614.16's transition from a non-effect event to an event modified by an effect. The affected controller chooses ordering when multiple effects apply; exact source incarnation and ability index can apply only once to that event. Simultaneous counter recipients are ordered APNAP and quantities commit together.

A token event retains all factory/count groups in one event, with a shared used-effect set. Addition, multiplication and artifact-to-Dragon replacement re-evaluate this entire set before any token enters. Checked arithmetic and object allocation retain action-level rollback on failure. Every actual newcomer is installed before entry observers are evaluated. Ordinary creation with no applicable replacement retains a direct path without an owned replacement frame.

Job Select attaches to one chosen actual newly created creature, including an added Frog; it never silently selects the last Hero. Mobilize requests defenders for every actual post-replacement token and retains all exact created incarnations in its delayed sacrifice. Added tokens inherit the original creation's tapped/attacking instructions. Explore and connive preserve their separate private continuations while counter ordering is resolved.

All 84 currently executable token factories, including complete immutable Offspring copies, have zero entry counters and no entry-counter rules. A structural native check enforces this closed catalogue fact. Follow-up counter instructions run only after token creation completes and use ordinary owned counter events. General nested token-entry counter replacement for a future factory with entry counters remains a separate continuation extension; such factories are not admitted by this feature.

The first compiling checkpoint passes all 1,577 library-native tests, including seven new replacement groups, and all-target Clippy. Focused cases cover both seats, noncommuting counter/token order, actual paid Job Select, actual attacking Mobilize with player and planeswalker defender choices, delayed sacrifice, initial loyalty versus loyalty cost, exact incarnation rejection and clone/restore/replay. Full compiler, paid public API, Standard terminal games, provenance and independent review remain pending.

The next checkpoint fixes an independently found simultaneous-entry ordering error: a separate APNAP counter index list preserves the original entry move array and its Aura/life indices. The reviewer's mixed-owner Ajani regression passes for both active players. Twelve focused native groups now pass, including empty/nonempty Explore continuations, sequential connive, late quantity overflow rollback and real activated sacrifice residuals. Six strict compiler methods pass in 0.245 seconds. Two fresh public methods pass in 77.992 seconds, covering 30 actual paid scenarios in both seats: all nine complete bodies, real Caradora search, both noncommuting counter/token orders and actual created Hero/Frog Job attachment choices. This initial public run uses the preserved pre-APNAP-fix release library; final fresh-library validation remains pending.
